## 采集策略

每个 frame 内按以下顺序采集，四类来源互补，避免遗漏：

1. `<img>`：`currentSrc`、`src`，以及 `data-src` / `data-lazyload` / `data-ks-lazyload` / `data-original` / `data-lazy-src` / `data-url` / `data-img` 等 18 个懒加载属性
2. `srcset` / `<picture><source>`：取描述符（`2x`、`800w`）最大的一项
3. `background-image`：扫描常见容器元素的计算样式（上限 9000 个节点，避免长详情页卡顿）
4. 源码文本：用正则从 `document.documentElement.innerHTML` 中提取图片 URL，捞出尚未渲染进 DOM（数据已在接口返回）的图

## 非商品图过滤

按"域名 → 路径 → 文件名关键词"三级过滤，关键词只匹配文件名，避免误伤带随机串的哈希文件名：

- 静态资源域名：`assets.alicdn.com`、`static.360buyimg.com`、`static.pinduoduo.com` 等
- 静态资源路径：`/tps/`、`/img/blank`、`/img/loading`、`/iconfont`
- 文件名关键词：`logo`、`icon`、`avatar`、`qrcode`、`placeholder`、`loading`、`spacer`、`1x1`、`btn_`、`sprite`、`kefu` 等
- 尺寸规则：宽高都小于 120px 的丢弃；非平台图床的图片需至少一边 ≥ 200px

## 需要实测确认的部分

以下细节随平台改版变动，代码中按"通用策略"处理，未做硬编码猜测，实际投产前建议在真实页面上用下面的探测脚本核对：

- 淘宝新版详情页的进销存/直播模块是否引入了新的图床域名
- 京东描述 iframe 的域名与懒加载属性是否有变化
- 拼多多商家版商品详情页（`mms.pinduoduo.com/goods/...`）的图片挂载方式（真实 `<img>` 还是 canvas/背景图）
- 是否有新的图片 CDN 域名需要加入 `manifest.json` 的 `host_permissions`

### 探测脚本（在商品详情页按 F12，粘贴到 Console 执行）

```js
// 1) 列出页面里的所有 iframe 及其来源域（确认详情长图在哪个 frame）
[...document.querySelectorAll('iframe')].map(f => f.src || f.getAttribute('data-src'))

// 2) 统计 img 用到的属性组合（确认懒加载属性名）
[...document.querySelectorAll('img')].reduce((acc, img) => {
  const key = [...img.attributes].map(a => a.name).filter(n => /^(data-|src)/.test(n)).sort().join('|');
  acc[key] = (acc[key] || 0) + 1;
  return acc;
}, {})

// 3) 列出图片域名分布（确认是否需要扩 host_permissions）
[...new Set([...document.querySelectorAll('img')].map(i => i.currentSrc || i.src)
  .filter(Boolean).map(u => new URL(u).hostname))]

// 4) 统计背景图使用情况（确认是否需要扫描 background-image）
[...document.querySelectorAll('div,section,a,span')]
  .filter(el => (getComputedStyle(el).backgroundImage || '').includes('url(')).length

// 5) 抽查某张图的原图地址是否可直连（把 URL 换掉）
await fetch('把图片地址粘贴到这里', { credentials: 'omit' }).then(r => r.status)
```

拿到结果后：

1. 新的图片域名 → 追加到 `manifest.json` 的 `host_permissions`
2. 新的懒加载属性名 → 追加到 `src/content/collector.js` 的 `LAZY_ATTRS`
3. 新的缩略图地址形态 → 追加到 `src/shared/platforms.js` 对应平台的 `cleanUrl`，并在 `tests/pipeline-smoke-test.js` 补一条断言
4. 新的详情页 URL 形态 → 追加到对应平台的 `detailPage`
